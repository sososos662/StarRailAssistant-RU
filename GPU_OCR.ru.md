# Ускорение OCR через DirectML

GPU-компоненты находятся внутри переносимой папки программы. Системный Python,
CUDA, службы, изменения PATH и отдельная установка драйверов не нужны.
Существующие пользовательские настройки и сохранения SRA в AppData не переносились.

## Что ускорено

RapidOCR использует ONNX Runtime DirectML для моделей PP-OCRv6. Это ускоряет
распознавание текста: имён, монет, уровня магазина, раунда, надписей событий
и результатов. Нажатия, анимации игры и поиск шаблонов OpenCV от этого
автоматически не ускоряются.

На Ryzen 5 2600 + Radeon RX 590, в последовательном сравнении 22 сохранённых
областей экрана, по три прогретых повтора на вариант:

| Вариант | Сумма медиан 22 областей |
| --- | ---: |
| Исходный CPU, native ONNX Runtime 1.27.0 | 11,17 с |
| CPU, native ONNX Runtime 1.24.4 | 11,25 с |
| GPU DirectML, native ONNX Runtime 1.24.4 | 4,09 с |

Это приблизительно в **2,73 раза быстрее для данного набора OCR**, а не для
всей партии. Замер сделан без работающей игры; влияние одновременной нагрузки
игры на GPU и полное время партии пока не измерены. Холодная компиляция GPU
для нового размера изображения может делать первые вызовы медленнее.

В настоящем компилированном SRA-cli.exe на тех же 22 областях текст и
координаты совпали с исходным CPU; максимальная разница оценок уверенности
составила 0,00002. Решения на проверенных порогах уверенности не изменились.
Модели, пороги, двухкадровые проверки, TTL 60 секунд, стратегия и ввод F/D
не менялись.

## Состав и версии

- Неизменённый компилированный Python API ONNX Runtime: **1.27.0**.
- Подключённые нативные библиотеки из официального onnxruntime-directml: **1.24.4**.
- RapidOCR: **3.9.1**; прежние модели, без повторного скачивания.
- Точная комбинация проверяется отдельно: строка `onnxruntime.__version__`
  показывает версию API; `onnxruntime.get_version_string()` — native runtime.
  Нельзя выдавать эту комбинацию за пересборку всего ONNX Runtime до 1.24.4.
- Происхождение и контрольные суммы: `gpu_ocr_runtime.json`.
- Лицензии поставщика: `onnxruntime/directml/`.

## Включение и CPU

В `rapidocr/config.yaml`, в разделе `EngineConfig.onnxruntime`:

```yaml
use_cuda: false
use_dml: true
dml_ep_cfg: null
```

Не подставляйте произвольный словарь в `dml_ep_cfg`: в RapidOCR 3.9.1
он может попасть в ONNX Runtime как DictConfig и вызвать откат на CPU.
Значение `null` использует штатный путь выбора адаптера.

Для принудительного CPU установите `use_dml: false` и полностью перезапустите
SRA. CPU-провайдер входит в тот же комплект библиотек. На копии программы
проверены как принудительный CPU, так и автоматический откат при ошибке
инициализации GPU. Это не обещание восстановления после любой ошибки
драйвера или нехватки видеопамяти во время уже идущего распознавания.

## Переносимость и воспроизведение

Готовую папку программы переносите целиком: exe, DLL, `rapidocr/models`,
конфигурацию и ресурсы. Не копируйте отдельно один DirectML.dll. Работа
проверяется также из другой папки с PATH, содержащим только каталоги Windows,
без PYTHONHOME, PYTHONPATH или виртуального окружения. Модели и загруженные
OCR-библиотеки должны находиться именно внутри перенесённой папки.

Исходный архив содержит официальный wheel в `vendor/`, закреплённый SHA256,
и `scripts/prepare_gpu_payload.py`. Этот вспомогательный сценарий требует
Python как инструмент сборки, но не устанавливает пакеты и не трогает
готовую программу. Пример из корня исходников:

```text
python scripts/prepare_gpu_payload.py --app ../dist/StarRailAssistant_v2.25.0-beta.1_RU --output gpu_payload
```

Сценарий создаёт переносимый набор изменяемых файлов для упаковщика.
На другом ПК готовому SRA этот Python не нужен. Не запускайте старые
сценарии упаковки, предполагающие исключительно CPU-библиотеки.

Протокол исходного локального эксперимента сохранён отдельно от публичных
исходников: он включает пользовательские кадры и не публикуется автоматически.
Границы доказанного и процедура проверки описаны в `docs/TESTING.ru.md`;
свежая сборка без обращения к приватному evidence — в `docs/BUILDING.ru.md`.
