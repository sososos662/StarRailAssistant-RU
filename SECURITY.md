# Безопасность и приватность

## Что не публиковать

Никогда не загружайте `%APPDATA%/SRA`, реальные `settings.json`, `extensions.json`,
`current_run.json`, cookies, пароли, CDK, webhook URL, access tokens и целые
архивы логов без проверки. Скриншоты могут содержать UID, ник и другие сведения.
Файлы диагностических квот не являются автоматически обезличенными.

Перед Issues замените имя/UID/пути маркерами и уберите секреты, включая URL-query
параметры. Если нужен исходный кадр для воспроизведения, сначала согласуйте
безопасный способ передачи. Отредактированный пример лучше полного архива.

Для уязвимостей используйте Private vulnerability reporting / Security advisory
этого репозитория, если владелец включил функцию. В противном случае сначала
откройте Issue **без секретов и эксплуатационных персональных данных** с просьбой
о приватном контакте. Не отправляйте проблему форка на личные адреса upstream.

## Запуск

- Не отключайте антивирус, SmartScreen или другие защитные механизмы по просьбе
  неизвестного распространителя. Сверяйте источник и SHA256 Release assets.
- Запрос UAC в desktop унаследован от upstream; автоматизация обладает
  возможностью отправлять ввод. Запускайте только проверенный исходный код/бинарник.
- Не размещайте WebUI, API или MCP во внешней сети без защищённого канала и
  аутентификации. Используйте loopback и настройте непустой случайный AccessToken.
  Снимок исходного `appsettings.json` с пустым токеном не является безопасной
  конфигурацией для публичного сервера.
- Штатный upstream-updater может заменить модифицированные компоненты.
- Нет гарантии отсутствия санкций со стороны игры или безопасности аккаунта.

## Публикация и CI

CI форка использует `contents: read`, не получает публикационные секреты и не
использует `pull_request_target`. Унаследованные публикующие workflow отключены.
Релиз размещайте вручную только после проверки соответствия бинарников исходникам,
полноты лицензий и исключения личных данных. [Чек-лист](docs/PUBLISHING.ru.md).
