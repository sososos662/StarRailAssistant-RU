# Сборка Windows x64

Готовому пользователю нужен ZIP из Releases, не эти инструменты. Сборка выполняется
локально, без запуска игры и без публикации. Внутренняя версия — `2.25.0-beta.1`,
ревизия форка — `FORK_VERSION`.

## Инструменты

- **Python 3.12 x64**, не Python 3.13.
- **.NET SDK 10** (не только Desktop Runtime). Локально использован 10.0.403.
  Нестандартный путь передаётся `--dotnet` или `DOTNET_EXE`.
- Node.js `^22.18.0 || >=24.12.0`, **pnpm 12.4.2** из `packageManager` WebUI.
- Nuitka и C-компилятор, обычно кэш MinGW, скачиваемый Nuitka при первом запуске.
- Для сборки с `--no-restore` ранее должны быть восстановлены соответствующие
  NuGet-пакеты и зависимости WebUI. Это не нужно путать с использованием старых EXE.

Из корня исходников, в отдельном Python-окружении:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install ".[full,dev]" nuitka ordered-set zstandard flake8
corepack enable
```

Зависимости приложения закреплены в `pyproject.toml`, WebUI — в `pnpm-lock.yaml`,
NuGet — в `.csproj`. Транзитивные зависимости Python/NuGet и версия компилятора
не заморожены полностью: **побитовая воспроизводимость не обещается**. Комплект
содержит `BUILD_INFO.json` с точными исходными хешами и Python-версиями; это
воспроизводимая процедура, а не заявление о byte-identical результате на любом ПК.

## Модели

Три файла и их URL/SHA256 перечислены в `ocr-models.json`. Используйте существующую
папку `rapidocr/models` через `--models-dir`, чтобы не скачивать их ещё раз.
Модели не включены в исходный GitHub ZIP; в готовый runtime они включаются.
При несовпадении SHA256 сборка останавливается, а не подменяет модель.

## Проверка плана без сборки

Укажите **новый, ещё не существующий** каталог вне исходников:

```powershell
.venv\Scripts\python.exe scripts/build_ru.py --output ../build-ru-check --models-dir ../models --plan
```

## Чистая сборка

Первый запуск с явно разрешённым скачиванием зависимостей/моделей/компилятора:

```powershell
.venv\Scripts\python.exe scripts/build_ru.py --output ../build-ru-1 --ocr directml --allow-downloads
```

С готовыми зависимостями, моделями и кэшем компилятора:

```powershell
.venv\Scripts\python.exe scripts/build_ru.py --output ../build-ru-2 --models-dir ../models --ocr directml
```

Без `--allow-downloads` модели не скачиваются, `pnpm install` не вызывается.
NuGet restore создаёт новые assets, используя кэш пакетов и пустой локальный
feed вместо сети; `dotnet publish` получает `--no-restore`. При нехватке зависимостей команда
завершается ошибкой, не устанавливает их глобально. Существующий `LOCALAPPDATA`
нужен только для кэша C-компилятора. APPDATA/TEMP для дочерних процессов изолированы.

Для чистой CPU-поставки замените `--ocr directml` на `--ocr cpu`. DirectML-вариант
использует проверенную комбинацию Python API ONNX Runtime **1.27.0** и native
DirectML **1.24.4**, а не устанавливает wheel поверх build-окружения. Четыре
native-файла извлекаются из закреплённого wheel; уведомления сохраняются.
[Подробности и fallback](../GPU_OCR.ru.md).

Сценарий:

1. Проверяет версии API и SHA256 моделей.
2. Собирает WebUI с type-check, свежий Nuitka backend и оба .NET publish output.
3. Не использует старый `main.dist` или установленную программу как вход.
4. Добавляет исходные ресурсы, модели, конфигурацию, runtime и доступные лицензии.
5. Проверяет неизменность исходников, записывает манифесты и проверяет CRC ZIP.
6. Создаёт `artifacts/*.zip` и `.sha256`, включая соответствующие исходники.

Для .NET явно используются `DebugType=None` и `DebugSymbols=false`: простое
исключение `.pdb` из ZIP недостаточно, поскольку путь к локальному PDB может
оставаться внутри DLL/EXE. Для обоих проектов используется **новый общий
`--artifacts-path`**, чтобы кэш скомпилированного Avalonia XAML из старого `obj`
не возвращал прежний PDB-путь даже при Rebuild. `PathMap` нормализует путь исходников.
В поставке дополнительно проверяется отсутствие
домашнего пути сборщика в байтах EXE.

Старые `--package-only` и `--backend-only` намеренно больше не поддерживаются:
они позволяли случайно смешать актуальные исходники со старым backend.
Журналы сборки остаются в `logs/`; не прикладывайте их к публичному Release без очистки.
`scripts/package.py` сохранён как upstream-инструмент и может публиковать в R2 —
для форка его **не запускайте**. `npm run build` перенаправлен на безопасный сценарий.

## После сборки

ZIP — кандидат, не сертификат прохождения игры. Выполните
[offline-проверки](TESTING.ru.md), проверьте подписи/происхождение runtime DLL,
лицензии, перенос в новую папку и работу OCR на сохранённых кадрах CPU/DirectML.
Публичный workflow `Manual fork build` создаёт **Actions artifacts**, не GitHub Release.
Он ещё не проверен в будущем репозитории; первый запуск нужно просмотреть вручную.

## Происхождение текущей локальной поставки

Попытка полного свежего Nuitka-прогона была прервана перезапуском среды и не
объявляется успешной. Для этой поставки сохранено уже проверенное скомпилированное
ядро 27.10 после проверки неизменности `main.py` и всех Python-файлов `SRACore`.
Внешние расширения/JSON обновлены, WebUI и оба .NET EXE пересобраны и проверены.
Это явно отражено в `BUILD_INFO.json`; неизменённое ядро повторно прошло реальные
OCR-пробы. Сценарий выше предназначен для полной сборки с нуля, а не для
маскировки переиспользованного ядра как новой компиляции.
